# Development Workflow — منصة التشريعات اليمنية

> **المرجع التفصيلي الوحيد لدورة العمل.** اقرأ هذا الملف قبل أي تغيير تطويري.

## 1.Issue قبل كل عمل

- ابحث عن قضية قائمة قبل إنشاء جديدة.
- قضية مستقلة لكل مشكلة أو نتيجة مترابطة.
- قسّم الطلب الكبير إلى قضايا فرعية تحت قضية جامعة.
- يجب أن تتضمن: عنوان، وصف، خطوات إعادة إنتاج، معايير قبول، خطة اختبار.

## 2. إنشاء فرع من develop

```bash
git checkout develop
git pull origin develop
git checkout -b feat/NNN-description
```

- `NNN` = رقم القضية
- لا تطوّر على `develop` أو `main` مباشرة.

## 3. التطوير المحلي

- نفّذ معايير قبول القضية كاملة.
- أضف اختبارات سلوك للحالات المهمة.
- لا تغيّر التوقعات لإخفاء خطأ.

## 4. الفحص المحلي

```bash
bun run lint        # ESLint
bun run db:push     # تحقق من توافق قاعدة البيانات
bun run dev         # تحقق من التشغيل
```

- لا تعلن نجاح اختبار لم تُنفذه.
- لا تتجاهل فشل اختبار.

## 5. Commit والرفع

```bash
git add -A
git commit -m "feat(scope): description (#NNN)"
git push -u origin feat/NNN-description
```

- راجع الملفات المضافة والفرق الفعلي قبل كل commit.
- اجعل التغييرات مترابطة ورسالة commit واضحة.

## 6. إنشاء Pull Request

- من فرع القضية إلى `develop`.
- اربط القضية: `Issue: #NNN`
- اذكر: المشكلة، السبب، السلوك الناتج، التغييرات، الاختبارات.

## 7. شروط الدمج في develop

1. القضية ومعايير قبولها منفذة.
2. فرع الوجهة هو `develop`.
3. جميع فحوص GitHub Actions نجحت للنسخة الحالية.
4. لا تعارض دمج.
5. PR جاهز ولا يحوي أسرارًا.

## 8. بعد الدمج

- تحقق من حالة `merged` ووجود النتيجة في `origin/develop`.
- انتظر فحوص ما بعد الدمج.
- أغلق القضية بدليل.
- نظّف فرع المهمة.
- حدّث `develop` المحلية: `git checkout develop && git pull`.

## 9. التعامل مع التعارض

```bash
git checkout feat/NNN-description
git fetch origin
git rebase origin/develop
# حل التعارضات
git rebase --continue
git push --force-with-lease
```

- لا تستخدم `push --force` العادي.
- احترم تغييرات الآخرين.

## 10. التعامل مع الفشل

- إذا فشلت فحوص GitHub Actions:
  - اقرأ السجل، حدد السبب.
  - أصلح في فرع القضية نفسها.
  - ارفع وأعد الفحص.
- إذا فشل فحص ما بعد الدمج:
  - أنشئ قضية معالجة وفرع وPR.
  - أو PR تراجع عند الحاجة.
- لا تعتبر المهمة مكتملة رغم الفشل.

## 11. استئناف العمل بعد انقطاع

- اقرأ `AGENTS.md` و`worklog.md`.
- راجع Issues المفتوحة والفروع النشطة.
- لا تنشئ قضية أو فرعًا مكررًا.
- أكمل من أول بند غير منجز.
